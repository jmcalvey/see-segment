I then went through the example scripts to get an idea of the workflow and found that everything was working and didn't need any updates.
The second aspect of my work was looking over the new genetic algorithm library, StackGP, and beginning to get an idea of what it will look like to swap it in for DEAP. Per Dirk's advice, I started by looking at what inputs are needed to run the library, since this is how our library will communicate with the genetic search algorithm. It appears that the bare minimum arguments are a list of arrays for the input variables and an array of target values. There are also a number of optional arguments that can be used to customize the search.
The basic workflow starts with providing the input and target variables. StackGP then initializes a population of possible models and evaluates them based on fitness and complexity. It selects models for the next generation and creates new models through crossover, mutation, or random generation. These new models are combined with models retained from the previous generation to form the next generation. The population is then cleaned by removing duplicate models and models that are too complex. This process is repeated until an ending requirement is met, such as a specified number of generations, a time limit, or a fitness goal.
StackGP uses the genetic algorithm to find the structure of the best functions, and then, as a final step, uses optimizeModel to optimize the numerical constants in those functions.
